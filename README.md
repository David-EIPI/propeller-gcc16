# propgcc-16
A GCC 16.2.0 C toolchain for the Parallax Propeller 1 (P8X32A).  See generated `CHANGES.md` for what differs from the original GCC 6 based propgcc.

This port grafts the original Propeller 1 support code - originally 
written for the [GCC C compiler by David Betz](https://github.com/dbetz/propeller-gcc) from GCC 6 onto the recent GCC 16.2.
The rest of this Readme file, the changelog and the patch files were
generated by Chatgpt Astra 6 model following my prompts.


The toolchain is self contained: compiler, assembler, linker, the full set of
binary utilities, `libgcc`, the C library, the Spin compiler and the board
loader.

## Prerequisites

A C and C++ compiler for your machine, plus:

    make  flex  bison  texinfo  git  wget
    gmp    (development headers)
    mpfr   (development headers)
    mpc    (development headers)

On Fedora / RHEL:

    sudo dnf install gcc gcc-c++ make flex bison texinfo git wget \
                     gmp-devel mpfr-devel libmpc-devel

On Debian / Ubuntu:

    sudo apt install build-essential flex bison texinfo git wget \
                     libgmp-dev libmpfr-dev libmpc-dev

`patch` works in place of `git apply` if you prefer (`patch -p1 < ...`).

## Installing into your home directory

This installs to `$HOME/propgcc-16`, which needs no root privileges and can be
shared by all of your Propeller projects.

    export PREFIX=$HOME/propgcc-16
    export PATH=$PREFIX/bin:$PATH

    mkdir -p ~/src && cd ~/src

### 1. Get the sources

    wget https://ftp.gnu.org/gnu/gcc/gcc-16.2.0/gcc-16.2.0.tar.xz
    tar xf gcc-16.2.0.tar.xz

`propgcc` supplies the Propeller back end, binutils, the C library, the Spin
compiler and the loader.  GCC 16.2.0 supplies the compiler itself.

Every one of those components is a **git submodule**, so a plain `git clone`
leaves `binutils/`, `gcc/`, `lib/`, `loader/` and `openspin/` as empty
directories.  They have to be checked out explicitly:

    git clone https://github.com/dbetz/propeller-gcc.git propgcc
    cd propgcc
    git submodule update --init --depth 1 binutils gcc lib loader openspin
    cd ..

Name the five submodules rather than using `--recurse-submodules` or a bare
`git submodule update --init`.  The repository also lists `gcc4`, `ncurses`,
`spin2cpp` and `spinsim`, none of which are needed here, and `spinsim` is
registered with a `git://` URL - a protocol GitHub switched off in 2021, so
fetching it now hangs and takes the whole checkout down with it.

`--depth 1` keeps the download small; the `gcc` submodule is a complete GCC 6
tree and its full history is of no use here.  Drop the flag if you want the
history.

Check that the five directories are populated before going on:

    ls propgcc/binutils propgcc/gcc propgcc/lib propgcc/loader propgcc/openspin

### 2. Graft the Propeller back end onto GCC 16 and patch it

Both patch files ship with this port.

    cd gcc-16.2.0

    cp -a ../propgcc/gcc/gcc/config/propeller gcc/config/propeller
    mv gcc/config/propeller/propeller.c gcc/config/propeller/propeller.cc

    mkdir -p gcc/common/config/propeller
    cp ../propgcc/gcc/gcc/common/config/propeller/propeller-common.c \
       gcc/common/config/propeller/propeller-common.cc

    cp -a ../propgcc/gcc/libgcc/config/propeller libgcc/config/propeller

    git apply -p1 /path/to/00-propeller-target-registration.patch
    git apply -p1 /path/to/01-propeller-backend-gcc16.patch

    cd ..

### 3. Build binutils

The assembler and linker must exist before GCC is built.  This is 2017-era
source, so modern C diagnostics are relaxed.

    mkdir -p build-binutils && cd build-binutils
    ../propgcc/binutils/configure \
        --target=propeller-elf --prefix=$PREFIX \
        --disable-nls --disable-shared --disable-gdb --disable-werror \
        CFLAGS="-O2 -g -std=gnu17 -Wno-error \
                -Wno-implicit-function-declaration -Wno-implicit-int \
                -Wno-incompatible-pointer-types -Wno-int-conversion \
                -Wno-return-mismatch"
    make -j$(nproc)
    make install
    cd ..

### 4. Build the compiler and libgcc

    mkdir -p build-gcc && cd build-gcc
    ../gcc-16.2.0/configure \
        --target=propeller-elf --prefix=$PREFIX \
        --disable-nls --disable-shared --enable-languages=c \
        --without-headers --disable-libssp --disable-libquadmath \
        --disable-libatomic --disable-libgomp \
        --with-pkgversion="propgcc-16"
    make -j$(nproc) all-gcc
    make install-gcc
    make -j$(nproc) all-target-libgcc
    make install-target-libgcc
    cd ..

### 5. Build the C library

Also older source, so the same diagnostics are relaxed.  The library's
makefile appends the `LTO` variable to its compiler flags, which is the
supported way to pass these in.

    COMPAT="-std=gnu17 -Wno-error -Wno-implicit-function-declaration \
            -Wno-implicit-int -Wno-int-conversion \
            -Wno-incompatible-pointer-types \
            -Wno-builtin-declaration-mismatch -Wno-unused-but-set-variable"

    cd propgcc/lib
    make PREFIX=$PREFIX BUILD=$HOME/src/build-lib LTO="$COMPAT" -j4
    make PREFIX=$PREFIX BUILD=$HOME/src/build-lib LTO="$COMPAT" install

The install rule ends by copying licence files from a sibling `gcc/`
directory, which is not present in this layout, so it stops just before the
last two steps.  Finish them by hand:

    cp $HOME/src/build-lib/lib/obj/cog/crt0_cog.o \
       $HOME/src/build-lib/lib/obj/cog/crtend_cog.o $PREFIX/propeller-elf/lib/
    cp $HOME/src/build-lib/lib/obj/cog/libcog.a     $PREFIX/propeller-elf/lib/
    cd ../..

### 6. Build the Spin compiler and the loader

`propeller-load` compiles a Spin helper as part of its build, so `openspin`
has to be on the path first.

    cd propgcc/openspin
    make
    cp build/openspin $PREFIX/bin/
    cd ../..

    cd propgcc/loader
    make OS=linux TARGET=$PREFIX BUILDROOT=$HOME/src/build-loader
    make OS=linux TARGET=$PREFIX BUILDROOT=$HOME/src/build-loader install
    cd ../..

### 7. Put it on your path permanently

    echo 'export PATH=$HOME/propgcc-16/bin:$PATH' >> ~/.bashrc

Open a new shell, or `source ~/.bashrc`.

## Reproducibility

These instructions have been run end to end from pristine upstream sources
into an empty prefix, and the result compared against the toolchain the test
results in `CHANGES.md` were produced with:

* the 16 patched source files are byte-identical;
* the compiler generates byte-identical assembly for 1,260 test compilations
  (18 sources x 7 memory models x 5 optimisation levels x both `double` sizes);
* all 91 library and startup objects contain identical code;
* fully linked programs are byte-identical once debug sections are stripped
  (unstripped they differ only in the build paths recorded in DWARF).

## Checking the installation

    propeller-elf-gcc --version        # 16.2.0, tagged with the
                                       # --with-pkgversion you configured
    propeller-elf-ld --version
    propeller-load -h

Compile and link a test program:

    cat > hello.c <<'EOF'
    #include <stdio.h>
    #include <propeller.h>
    int main(void) { printf("hello from %u Hz\n", (unsigned)CLKFREQ); return 0; }
    EOF

    propeller-elf-gcc -Os -mlmm -o hello.elf hello.c
    propeller-elf-size hello.elf

With a board connected, load it into RAM and watch the output:

    propeller-load -Dclkfreq=80000000 -Dclkmode=XTAL1+PLL16X \
                   -p /dev/ttyUSB0 -r -t115200 hello.elf

Use `-e` instead of `-r` to write to EEPROM so the program survives a reset.
Your user account needs to be in the `dialout` group to reach the serial port.

## Relocating an installed tree

The installation is relocatable.  Copying or moving the whole directory works,
and the tools locate their libraries relative to their own path:

    cp -a $HOME/propgcc-16 /opt/propgcc-16
    export PATH=/opt/propgcc-16/bin:$PATH

## Installing alongside the old toolchain

The prefix is self contained and the programs are all named
`propeller-elf-*`, so an existing propgcc installation can stay where it is.
Whichever `bin` directory comes first on `PATH` wins; per project, override
`PROPPATH` instead of changing `PATH`.
